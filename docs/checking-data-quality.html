Learning outcomes

By the end of this module, you should be able to:

  1. Locate the main GGIR QC outputs.
  2. Explain clipping_score, calib_err, and complete_24hcycle.
  3. Distinguish the current per-recording QC report from the legacy participant-facing report.
  4. Triangulate numeric, visual, and operational evidence before documenting a quality decision.

Lesson 5.1

Locate Real QC Outputs

After GGIR processing, inspect the output folder before opening Stata. Exact output names depend on the installed version and options, so compare the folder against the run’s config.csv and the official GGIR output documentation.

Output Resolution and QC use
results/part2_summary.csv One row per recording; inspect duration, calibration status/error, clipping, completeness, and processing decisions.
results/part2_daysummary.csv One row per day; inspect recorded and valid hours, day/date fields, and day-level patterns before applying a study rule.
results/QC/data_quality_report.csv One row per recording; inspect corruption/short-file flags, calibration before/after, QCmessage, and format-specific file-health fields.
results/QC/plots_part2/*.png One low-resolution time-series plot per recording, with invalid segments highlighted.
results/file summary reports/report....pdf Current per-recording visualreport; intended to support QC of the Part 5 time series.
results/visualisation_sleep.pdf Optional Part 4 comparison of sleep-log guidance and detected sustained inactivity; useful when sleep QC is in scope.

Current versus legacy report: The current visualreport = TRUE creates files whose names begin with report...; the official parameter documentation says this report is specifically aimed at QC. The optional old_visualreport = TRUE creates legacy old_report... files. That older report was originally intended as a quick visual for participants and is not suitable for data-quality assessment.

Lesson 5.2

Read the QC Variables

These fields answer different questions and must not be collapsed into one pass/fail flag:

Field Official meaning Defensible use
clipping_score in part2_summary.csv Fraction of 15-minute windows in a recording affected by clipping; the official output guide states that it should be 0. Any non-zero value triggers investigation of the plot, device range, and affected duration; it is not a participant-behavior measure.
calib_err / calib_status in part2_summary.csv Static calibration error after auto-calibration and a summary of calibration status. Interpret with the status, plots, run configuration, and a pre-specified study rule. Do not assume a unit or cutoff from the variable name alone.
cal.error.start, cal.error.end, QCmessage in data_quality_report.csv Calibration error before/after auto-calibration and the resulting QC message. Check whether calibration improved and whether GGIR recorded a concern.
complete_24hcycle in part2_summary.csv A completeness score: the fraction of positions in the 24-hour cycle, evaluated in 15-minute windows, for which no valid data were available on any measurement day. Treat it as a recording-level coverage score. It is not a Boolean variable and does not identify whether a particular day is complete.
N valid hours in Part 2 output Number of hours with valid data for the relevant day/summary. Use the day-level value, together with the protocol definition, when constructing a study-specific valid-day indicator.

No single field replaces review of the raw-file history, day-level coverage, and plots. The official data-quality chapter describes the calibration, non-wear, time-gap, and clipping mechanisms behind these outputs.

Lesson 5.3

Visual Inspection

Numerical summaries can miss problems that are obvious in plots, and visual patterns can be misread without the numerical and field records. Review the following together:

  1. invalid segments, long gaps, or flat patterns that need to be reconciled with non-wear and file-health fields,
  2. abrupt shifts that may suggest device handling, placement change, or a recording artifact,
  3. unexpectedly short or long recordings,
  4. missing day-night cycles,
  5. calibration or clipping warnings,
  6. disagreement between deployment/download logs and processed timestamps.

Visual QC should be reproducible. Keep a QC log with:

  • participant ID,
  • file name,
  • GGIR run/configuration ID,
  • date reviewed,
  • reviewer,
  • evidence sources reviewed,
  • concern category and severity,
  • provisional status (pass, review, rerun, or exclude),
  • rationale and action taken,
  • whether a second reviewer is needed.

Do not infer “non-wear” from a flat line by appearance alone, and do not infer participant noncompliance from a software flag alone. Record the observation first; make the study decision only after triangulation.

Lesson 5.4

Valid-Day Review

A non-wear interval is a period classified as invalid because the device was likely not being worn under the configured GGIR method. A valid day is a study-defined day that meets pre-specified usable-data criteria. GGIR provides candidate inputs such as valid hours, non-wear percentages, and day identifiers; the study protocol determines the eligibility rule.

For the Pelotas/UFPel course example only, valid-day review uses:

  1. at least 4 valid days,
  2. at least 10 hours of awake wear per valid day,
  3. at least 1 weekend day.

These are not GGIR defaults and are not universal research standards. Do not use complete_24hcycle as a substitute for a day-level ≥10-hour calculation. First confirm the output variable, unit, day boundary, waking-window definition, and weekend convention used to evaluate each rule. Record exceptions before applying exclusions.

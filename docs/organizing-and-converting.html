Module 3

Organizing and Converting

Create a file system that makes every accelerometer file traceable to the participant, batch, software setting, and processing decision that produced it.

25–40 minutes File audit trail Conversion decision

Module guide: Bring a fictional or de-identified inventory of raw files; do not move or rename the only copy of study data while learning. The concept route requires only the examples and self-check. For the hands-on route, work in a practice folder. Your deliverable is a folder map, naming convention, batch log, and written conversion decision. You are finished when a second analyst can trace every practice file from its raw source to its processing status.

Learning outcomes

By the end of this module, you should be able to:

  1. Build a transparent folder structure for raw, converted, processed, and final files.
  2. Apply consistent file-naming rules and batch logs.
  3. Convert ActiGraph files in ActiLife when conversion is needed.
  4. Explain why .gt3x to .csv conversion is pipeline-dependent rather than universally required.

Lesson 3.1

Folder Structure

Use a folder structure that separates raw evidence from files created later in the pipeline. A simple structure is:

accelerometer_project/
  01_raw_downloads/
    batch_001/
      COMPLETE/
      INCOMPLETE/
  02_converted_files/
  03_ggir_input/
  04_ggir_output/
  05_qc_review/
  06_cleaned_data/
  07_stata_final/
  logs/

Raw downloads should be treated as read-only after the first handoff. If a file must be renamed, keep a log linking the original file name, new study ID, device ID, download batch, and operator.

Worked example: Pelotas/UFPel cohort
Separate each collection lot or batch before processing. Keep the original raw downloads, the conversion outputs, and GGIR outputs in different folders. This makes it possible to append lots later in Stata without losing the batch history.

Lesson 3.2

Naming and Batch Logs

Every file should be traceable to:

  1. participant or study ID,
  2. device serial number,
  3. collection lot/batch,
  4. download date,
  5. operator,
  6. file format and processing status.

Avoid names such as participant1.csv or newfile.gt3x. Prefer a naming pattern such as:

studyid_batch_deviceid_YYYYMMDD_raw.gt3x
studyid_batch_deviceid_YYYYMMDD_converted.csv

The exact pattern can differ across studies; the important rule is that another analyst can reconstruct where each file came from.

Lesson 3.3

ActiLife Conversion Workflow

Some workflows convert ActiGraph files to .csv for software that cannot read .gt3x. If conversion is part of the approved workflow, use a batch process rather than manual one-by-one exports.

Recommended ActiLife conversion steps:

  1. Open ActiLife.
  2. Go to File -> Import/Export/Convert.
  3. Choose RAW to RAW.
  4. Select GT3X -> CSV (batch).
  5. Select the input folder containing .gt3x files.
  6. For the documented GGIR raw-CSV export, set TimeStamps to Off, as required by GGIR’s ActiGraph CSV guidance. For any other downstream workflow, confirm and document its schema rather than copying this setting automatically.
  7. Check create subfolder so converted files are separated from the originals.
  8. Run the batch conversion and save the conversion log.

Menu labels and defaults can differ by ActiLife version. Record the version used and verify the current documentation before converting study files.

Quick summary Brief review

Organize raw files with stable IDs, predictable folders, descriptive file names, and a conversion log. Preserve the original .gt3x files; batch-convert to CSV only when a downstream workflow requires it, because GGIR can process .gt3x directly.

Lesson 3.4

Is Conversion Always Necessary?

No. GGIR can directly read .gt3x files, so converting .gt3x to .csv is not required for the GGIR pipeline taught in Module 4. Conversion is useful only when a downstream script, external software package, data-sharing requirement, or audit workflow specifically needs .csv.

Pipeline decision: Convert only if the approved downstream workflow requires CSV. For the GGIR path in this course, preserve .gt3x as the raw input and document any additional export separately.

If a batch begins with 100 .gt3x files and every file converts once, expect 100 original raw files plus 100 converted outputs in separate locations. Reconcile the input count, successful-output count, failed conversions, duplicate names, and log before processing.

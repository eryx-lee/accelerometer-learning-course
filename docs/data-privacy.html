Privacy and learner control

Learning-data privacy

Public reading does not create an identifiable learning record. Signing in and opting in enables secure progress synchronization, course reporting, and certificate verification.

Notice version 2026-08-11-v1 Effective August 11, 2026 24-month inactivity retention Not an official UIUC record

Your choice

You may read the course overview, course information, this notice, and other public information without signing in. To enter the questionnaire, learning modules, or completion pathway after the data service is enabled, you must sign in with GitHub, confirm that you are at least 13 years old, and actively accept this notice. Declining does not create an identifiable course record and does not prevent access to those public information pages.

This learning record is not used for UIUC grades, academic assessment, enrollment decisions, or an official UIUC credential.

Authentication and data collected

Selecting Continue with GitHub causes GitHub and the course authentication provider to process an OAuth account identifier, confirmed email address, and ordinary authentication security metadata before you decide whether to accept this course notice. The login asks GitHub for basic account identity and the user:email permission so a confirmed address can be obtained even if it is private on your profile; it does not request access to your repositories. Signing in alone does not create a course enrollment or store questionnaire, module, quiz, feedback, or certificate activity. An unused, non-staff authentication identity is covered by the same 24-month inactivity deletion schedule.

After you accept this notice, the course stores only the information needed to operate and evaluate the learning pathway:

  • the authentication account identifier and confirmed email address used to link the opted-in record;
  • your display name and entry-questionnaire answers;
  • course version, first entry, last activity, module views, and module-completion choices;
  • each fully submitted quiz attempt, selected option for each question, server-calculated correctness, score, and submission time;
  • optional module feedback and required final feedback that you choose to submit;
  • certificate eligibility, a one-way hash and the last eight characters of a high-entropy verification code, display-name snapshot, issue time, and active or revoked status; the complete code is returned to the learner but is not stored in the database; and
  • consent, export, deletion, and administrator-access audit events.

The course application does not intentionally collect date of birth, participant or patient data, health information, device fingerprint, advertising identifiers, precise location, or raw study data. Caption display preference remains on your device. To limit abuse of the public certificate verifier, the service derives a secret-keyed HMAC-SHA256 network fingerprint from ordinary request metadata; it does not store the raw IP address, raw user-agent string, or submitted certificate code in the rate-limit table. Those rate-limit counters expire no later than two days. Hosting and authentication providers may separately process ordinary security and delivery logs under their own notices.

Purposes and metric definitions

The records support learner progress, course improvement, support, aggregate reporting, and certificate verification. An identified course entrant is a signed-in learner for whom the server has created an enrollment. A question is counted only when a complete attempt is submitted. First-attempt and latest-attempt accuracy are reported separately. Visiting a module and completing a module are distinct. Module 8 completion and certificate eligibility are calculated from documented server rules rather than browser-supplied scores.

Access and disclosure

You can access your own record. Designated course administrators can access identifiable records only to operate, support, evaluate, and secure the course. Other learners cannot access your record. Administrative access and exports are audited.

The optional GitHub Issue action is separate and never copies your saved feedback. Anything you type and submit on GitHub is public. Never include sensitive information in GitHub Issues.

Retention, export, correction, and deletion

Identifiable learning records are scheduled for deletion after 24 months without course activity unless a shorter period is required. Security and deletion audit records may be retained separately when necessary to demonstrate that a request was completed.

After signing in, you can download a machine-readable copy of any existing record without accepting a new notice version. If no learner record exists, the dialog says so rather than creating one. You can also request deletion from the same controls before or after opting in; signing in but not accepting this notice does not prevent deletion of the authentication account. Deletion revokes any associated certificate verification, removes the centrally stored record from active systems, removes that account’s local learning cache and unsent queue from the current browser, and signs the browser out, subject to limited backup rotation and security obligations. You can correct your display name through the course record and contact the course steward through the LA PASSSTA Lab website for an unresolved access or correction problem. Do not send quiz answers or other sensitive course data through a public GitHub Issue.

Security approach

Authentication identifies the learner; database authorization independently limits every read and write. Access and refresh tokens are kept in per-tab session storage rather than persistent browser storage and are cleared locally on sign-out. Questionnaire answers, local quiz state, progress, feedback, and a returned certificate code may be held as a resilience cache in browser storage. When the central service is configured, that cache is separated by authenticated account so another account using the same browser does not inherit it. If the network is unavailable, an opted-in event waiting to synchronize may also remain in local storage, bound to that account identifier; it can contain questionnaire answers, selected quiz options, feedback, or progress. The server accepts offline events for no more than 30 days, and the browser automatically removes queued items once they are too old to be accepted. A permanent server rejection remains visibly marked as blocked only within that same 30-day maximum; the learning-record dialog lets the signed-in owner delete blocked unsent records immediately while preserving transient records that can still be retried. Like other browser storage, these local copies can be inspected by someone with access to the same browser profile. Signing out preserves the account-scoped cache and eligible unsent queue for that same account’s next sign-in, while Stop saving on this browser removes all of that owner’s unsent records. A successful account-and-data deletion removes that account’s learning cache and unsent queue from the current browser.

The course service validates request shape, ownership, course and question versions, timestamps, rate limits, and idempotency. It recalculates quiz scores and certificate eligibility on the server. Service credentials are not placed in the public repository, browser configuration, URLs, analytics, or logs. Because these are instructional self-checks, answer explanations remain part of the course content; server-side calculation protects record integrity but is not represented as proctored testing. Requests use HTTPS, and hosted database storage and backups follow the provider’s configured security controls.

Changes to this notice

Material changes receive a new notice version. Existing signed-in learners must accept the new version before additional identifiable learning activity is collected under it. The current version and effective date remain visible on this page.

Module 8

Knowledge Checking

Check whether you can apply the course workflow, not just remember vocabulary, before using real study data.

File types QC decisions Study rules

Learning outcomes

By the end of this module, you should be able to:

  1. Identify the correct file type for each processing step.
  2. Choose complementary QC outputs and interpret key fields accurately.
  3. Match GGIR parameters, bout settings, windows, and output names to their meanings.
  4. Select safe merge keys and apply study-specific eligibility rules without erasing audit evidence.
  5. Identify what must still be checked before using a course example on real data.

Final reflection

Make a Readiness Decision

Before using real study data, classify the pipeline as ready, revise, or seek review. “Ready” requires that you can show—not merely describe—the following:

  • the compatible input type and immutable source inventory,
  • the exact R/GGIR versions, time zones, script, and resolved config.csv,
  • pilot confirmation of ID extraction and expected outputs,
  • numeric, visual, and operational QC evidence with reviewer decisions,
  • the distinction between current QC reports and legacy reports,
  • the cleaned/full Part 4 sleep-file roles,
  • the configured thresholds, windows, and bout definitions,
  • asserted source keys and an explicit merge relationship,
  • pre-specified valid-day and exclusion flags with overlap counts,
  • a reproducible final dataset, log, dictionary, README, and release date.

Choose revise if any item is incomplete but can be resolved by updating the script or documentation. Choose seek review when the issue changes the scientific estimand, population-specific cut-points, sleep interpretation, or data eligibility rule.
